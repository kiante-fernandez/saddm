# Verification

| script | what it does |
|---|---|
| `parameter_recovery.py` | 100-config NUTS recovery study: parameters drawn by Latin hypercube at s = 1, data generated by the exact inverse-CDF sampler, fitted with numpyro. `OUT_DIR` / `SHARD` / `N_SHARDS` env vars support sharded cluster runs; results checkpoint per config and resume. |
| `recovery_figure.py` | Posterior-vs-truth panel for all seven parameters. |
| `compare_to_fortran.py` | Per-subject scatter (v0, v_val, v_time, a, t0, z) and k-sweep curves (those plus sv, sa, st) against the Fortran benchmark in `data/itc_amasino/`. |
| `likelihood_figure.py` | Analytic density against a 200k-trial Euler–Maruyama simulation that shares no code with the likelihood. |

The analysis scripts read `results/reference/` by default and regenerate the
published figures and numbers exactly; point `RESULTS` at a fresh run to
analyze a reproduction.
They write to `results/figures/` (gitignored) unless `OUT` says otherwise, so
a default run never touches the tracked reference figures.

## Conventions

- Everything is at diffusion coefficient **s = 1**; `a` is the full boundary
  separation and `sa`/`st`/`sz` are full widths of the uniform across-trial
  distributions. Ratcliff-convention (s = 0.1) values convert by ×10 on
  a, v, sv, sa.
- Recovery data comes from `sample_ddmsa_exact` (inverse-CDF of the analytic
  density), not Euler simulation: Euler overshoots the boundary and inflates
  recovered `a` and `sv` enough to masquerade as recovery failure.
- The recovery model samples non-decision time by its lower edge
  (`t_edge ~ U(0, min RT)`, `t = t_edge + st/2`); bounding `t` itself by
  min(RT) excludes the truth whenever `st > 0`.
- The Fortran programs report the start point mirrored (`z_fortran = 1 − z`);
  `compare_to_fortran.py` flips it before comparing.

## Results

Recovery over 100 datasets (500 trials each, 4 chains, no init jitter): a/z/v/t
at r = 0.93–0.98 with 95 % HDI coverage 0.92–0.93; sv/sa/st at r = 0.65–0.73.
At the R̂ ≤ 1.01 / 0-divergence gate (85/100), coverage is 0.91 (sv), 0.85 (sa)
and 0.95 (st). `sa` remains under-covered with median relative bias −0.26 and a
slope of 0.15 of recovered on true `sa/a`: at N = 500 it is weakly identified
and shrinks toward the `Beta(1.5, 3)` prior mean of a/3, so treat small-N `sa`
as an upper bound. The two non-converged configs (R̂ 1.5–1.7) have accuracy
1.00 and 0.04, where z and v are not separately identified. The study inverts
the same likelihood at the same `n_quad` it fits, so it checks the estimator,
not the quadrature. Per-subject ITC fits agree with the Fortran
benchmark at r = 0.95 (value coefficient), r = 0.97 (drift intercept and delay
coefficient), r = 0.99 (t0), r = 0.81 (a) and r = 0.89 (z). In the population
k-sweep, a, t0, z and st track the Fortran curve within 3–6 %; sv and sa do not
(both are weakly identified at these N and the two implementations disagree in
direction).
